# Risks

Ordered by how likely each is to stall the port. Each has an owner document and a mitigation that is already part of the plan.

| # | Risk | Impact | Likelihood | Mitigation |
|---|---|---|---|---|
| 1 | **The WGSL compiler is a large project on the critical path.** Every native frame depends on it, and the corpus uses most of WGSL. | High | High | Corpus-driven: only constructs in the engine's real shaders block milestones. Triangle subset first, then grow by corpus coverage. Uniformity analysis and error-message parity are deferred. `spirv-val` and `metal` catch codegen bugs early. ([wgsl.md](wgsl.md)) |
| 2 | **Implementing WebGPU on Vulkan and Metal is large.** Validation, state tracking, memory allocation and barriers are each substantial. | High | High | Implement only what the engine calls (measured in [gpu.md](gpu.md#what-the-engine-needs)). Validation in one shared front end. Vulkan first and alone until Wave 1 runs; Metal after. |
| 3 | **Rendering parity is hard to reach pixel-exactly** across different GPUs and drivers. | Medium | High | ΔE thresholds rather than exact matches, comparable adapters (lavapipe on both sides), and the cheapest-observable rule: CPU and readback tests catch most differences before screenshots do. |
| 4 | **Upstream moves faster than the port.** Shallot is active (50 commits in the visible history, a release staged at the snapshot). | Medium | High | Weekly merges, the ledger, and the module map keep the gap visible and mechanical. Shaders are re-dumped automatically so rendering drift shows in parity. ([upstream.md](upstream.md)) |
| 5 | **TypeGPU-to-WGSL translation loses structure.** The resolved corpus flattens functions and renames identifiers, which makes hand-splitting into modules slow. | Medium | Medium | Use `names: "strict"` when dumping so authored names survive, and dump per function where TypeGPU allows it, not only per pipeline. |
| 6 | **macOS without Objective-C source.** Defining AppKit subclasses and calling Metal through `objc_msgSend` by hand is error-prone (calling conventions differ for struct returns on x86_64; arm64 is uniform). | Medium | Medium | Target Apple silicon (arm64) first, where `objc_msgSend` has one calling convention. A small typed wrapper per selector signature, tested on CI. |
| 7 | **Linux desktop fragmentation** (X11 vs Wayland, client-side decorations, compositor protocol support). | Medium | Medium | X11 first, which also runs under XWayland. Wayland second with run-time protocol detection. |
| 8 | **Audio decoding** (Vorbis) and JPEG are fiddly to get bit-close to browser decoders. | Low | Medium | Tolerance-based comparison; only one Ogg and one JPEG asset in the examples. |
| 9 | **HTTPS without third-party crates.** `std` has no TLS, so `shallot-cli publish` (itch.io, Cloudflare) cannot upload by itself. | Low | Certain | The CLI shells out to the platform's `curl` or butler, which are tools rather than linked dependencies. The engine itself never needs the network. |
| 10 | **Accessibility regresses** compared with DOM-based HUDs (ARIA labels, screen readers). | Low | Certain | Labels are kept as data in `ui` so a platform accessibility bridge can be added after parity. Recorded so it is not forgotten. |
| 11 | **Browser-only examples and claims** (`embedded-scene`'s host page, Vite hot update, cross-origin isolation e2e tests) have no native meaning. | Low | Certain | Each is reinterpreted or marked not applicable with a reason in the example's status, never silently dropped. |
| 12 | **Physics kernel native threading** behaves differently from WASM atomics (spurious wake-ups, oversubscription). | Medium | Low | The scheduler already has a native path and tests at 2 and 8 threads. Hash equality between single-thread and multi-thread schedules is a CI gate. |
| 13 | **The bindings boundary ossifies too early** and then blocks engine refactors. | Medium | Medium | Boundary versioning from day one; the boundary is built after the engine core API settles (Phase 2, not Phase 1); everything is additive within a major version. |
| 14 | **Scope of `unsafe`.** Hand-written FFI across three OSes and two GPU APIs is a large unsafe surface. | Medium | Medium | Unsafe is confined to named crates, every block has a `SAFETY` comment, layout assertions on every FFI struct, Miri on the safe engine crates, and validation layers in GPU tests. |
