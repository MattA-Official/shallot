# 04 · Requirements on the boundary

This is the contract between this plan and the porting plan. The boundary itself is designed in
[`docs/porting/`](../../porting/); this list says what the TypeScript binding needs from it, and
why. Every requirement is phrased for any host language, not just TypeScript: if a requirement
only helps TypeScript, it does not belong in the boundary and the binding handles it on its side.

These were sent to the porting-plan thread on 2026-10-29. Where the porting plan answers a
requirement, link the section here and mark it.

| ID | Requirement | Why the binding needs it | Status |
| --- | --- | --- | --- |
| R1 | Components can be registered at runtime from a schema: a stable key, an ordered field list (`f32`, `i32`, `u32`, `u8`, `u16`, `f16`, `vec2`, `vec3`, `vec4`, `entity`), and default values. Rust-declared components go through the same registry. | TypeScript declares components with `component(name, {...})` at module load. | Sent |
| R2 | Each field's storage is a contiguous structure-of-arrays column in engine memory, exposed as `(ptr, byteLength, generation)`. The generation changes whenever the column moves. Dirty bitsets and change ticks are exposed the same way. | Zero-copy typed-array views; per-entity reads and writes never cross the boundary. | Sent |
| R3 | Host systems: register a function pointer plus user data with a name, group, `first`/`last`/`terminal`, and `before`/`after` edges naming any system (engine or host) by stable name. The engine calls it once per system per tick, never per entity. | TypeScript `System` objects. | Sent |
| R4 | Bulk operations: fill a caller-provided buffer with the entity ids matching a query (with a "needs N more" result if it is too small); batch create, add and remove. | Iterating queries and spawning scenes without thousands of calls. | Sent |
| R5 | Resources come in two kinds: plain-data resources described by a schema and exposed as memory (like R2), and handle resources whose operations are boundary functions. | `ambient.color = ...` and `materials.add(...)` respectively. | Sent |
| R6 | No unwinding across the boundary. Every fallible call returns a status code; a per-world (or per-thread) last-error UTF-8 string carries the message. Strings are always `(ptr, len)` UTF-8, never NUL-terminated. | JavaScript exceptions with today's messages; no C string conventions. | Sent |
| R7 | The host can drive time: `step(dt)` and `tick()` on a world with no window, as well as a pumped `frame()` for windowed apps that returns promptly instead of blocking in an OS event loop. | `bun:test` suites build worlds headlessly; Bun must keep its event loop alive between frames. | Sent |
| R8 | One boundary definition produces both `wasm32` exports and native dynamic-library exports, with the same names and signatures (pointers are 32-bit on wasm; sizes are passed as `usize`-width values on both). | One transport interface in TypeScript. | Sent |
| R9 | The engine emits a reflection dump (JSON, generated by the engine itself) listing built-in components with schemas and defaults, resources, enums and their values, plugins and their dependencies, system names, and handle-resource functions with argument layouts. Versioned with the boundary. | Generates tier B and C of the TypeScript API; keeps the binding in step with upstream. Equivalent of Godot's `extension_api.json`. | Sent |
| R10 | The GPU layer is reachable through integer handles (adapter, device, buffer, texture, sampler, pipeline, bind group, encoder, pass, query set), and materials and passes accept WGSL source text. | Native WebGPU object model for user GPU code and TypeGPU; TypeGPU-authored shaders reach the engine as WGSL. | Sent |
| R11 | Snapshot and restore accept host participants: callbacks that write and read an opaque byte blob for state the host owns. | `Plugin.recovery`, used by save-and-load and determinism tests. | New |
| R12 | Asynchronous operations (asset loads, GPU readback, `sync`) return a ticket; completion is reported by `frame()`/`step()` or a poll call. No host callbacks from engine worker threads. | JavaScript callbacks must run on the JavaScript thread; promises are built on tickets. | New |
| R13 | Boundary versioning: a single `shallot_boundary_version()` entry point, checked first, plus feature queries for optional parts. Additive changes keep the major version. | The npm package ships a specific engine build but should fail clearly on a mismatch. | New |
| R14 | Input injection functions mirroring today's (`press_key`, `release_key`, `pointer_move`, `touch_point`, `cancel_touch`, `pointer_lock_changed`, `resize_viewport`, `focus_canvas`, ...). | Browser glue forwards DOM events through them; tests drive input through them. | New |
| R15 | On wasm, the engine's own imports for WebGPU, input, audio, fetch and time are a documented, stable list. | The binding's L1 glue is the implementation of those imports. | New |

## Things the binding deliberately does not need

- **Per-entity accessor functions** such as `get_f32(world, component, field, eid)`. They would
  exist for languages without shared memory, but TypeScript must not use them on hot paths.
- **Host-allocated component storage.** The engine owns all ECS memory.
- **Callbacks from worker threads.** See R12.
- **A C header.** The TypeScript glue is written against the Rust definitions and the reflection
  dump.
